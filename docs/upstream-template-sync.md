# 上游模板自动更新

上游来源为 `saicaca/fuwari` 的 `main` 分支。工作流为
`.github/workflows/sync-upstream.yml`，每天北京时间 06:23 检查一次，
也可以在 GitHub Actions 中手动运行 `Sync upstream template`。

## 合并规则

- 上游没有新提交时直接结束。
- 有更新时使用 Git 普通合并，保留本仓库的文章、站点配置和定制代码。
- 合并成功后，安装锁文件中的依赖，执行 Biome、Astro 类型检查及完整生产构建。
- 全部通过才推送到 `main`，并显式触发质量检查、构建检查和 GitHub Pages 部署。
- 冲突、依赖安装失败、检查失败或主分支并发更新导致推送失败时，工作流报错，主分支保持原样。

GitHub Actions 使用仓库自带的 `GITHUB_TOKEN`，无需配置个人令牌。
由于此令牌的推送不会再次触发普通 `push` 工作流，更新流程通过
`workflow_dispatch` 显式启动后续检查和部署。

## 首次建立历史关系

本仓库由 GitHub 模板创建，与上游没有共同 Git 历史。
已核对初始提交的文件树与上游 `6d39b0d` 完全一致。
首次配置时，以此提交作为已接收模板的历史基线，通过仅连接历史、
保留本站文件的合并提交建立关系。之后的上游提交才作为增量合并，
不会把整个模板目录重新覆盖到本站。

## 失败后处理

从失败运行的日志确认冲突文件或失败检查，在独立分支中合并上游并修复，
通过相同检查后再合入 `main`。自动流程不会采用整文件覆盖或强制推送来处理冲突。
